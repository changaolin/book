Solidity基础

数据结构

注意事项

  • Mapping不支持直接遍历，需结合其他结构记录键值。
  • 动态数组操作（如push）会增加Gas，尽量减少不必要的操作。

基础数据类型

  • uint: 无符号整数，uint256是默认类型，表示0到2^256-1的整数。可以使用不同的位宽，如uint8、uint16等。
  • int: 有符号整数，范围为-2^(n-1)到2^(n-1)-1。
  • bool: 布尔类型，只有true和false两个值。
  • address: 20字节的以太坊地址类型，分为address和address payable（后者可用于接收以太币）。
  • bytes1 ~ bytes32：固定大小字节数组

引用类型

  • string：动态大小的 UTF-8 编码字符串

  • bytes：动态大小的字节数组

  • 数组：如 uint[]（动态大小）或 uint[5]（固定大小）

  • 结构体 (Struct)：自定义的复杂数据类型，例：struct Person { string name; uint age; }

    • struct Status{
        string name;
        string message;
    }

  • 映射 (Mapping)：键值对存储，如 mapping(address => uint)

    • mapping(string => uint256) private nameToFavoriteNumber;

  • library

  • modifier: 用于在函数执行前后添加检查或修改行为

    • modifier 修饰符名称(参数) {
    // 前置条件检查
    require(条件, "错误消息");
    _; // 表示被修饰函数的代码
    // 后置操作（如果有）
}

modifier onlyOwner() {
    require(msg.sender == owner, "只有合约拥有者才能调用此函数");
    _;
}

function withdrawFunds() public onlyOwner {
    // 提款逻辑
}

    • 可以组合多个modifier

    • 执行顺序：从左到右依次执行modifier

    • 可以在modifier中使用参数

    • _;表示被修饰函数的代码插入点

  • memory：临时数据位置，函数调用结束即释放。适合在函数内处理临时数据。

  • storage：永久存储，数据保存在区块链上。默认的状态变量存储位置，Gas成本高。

  • calldata：只读数据位置，通常用于外部函数调用的参数。不可修改，效率高。

权限类型

  • public： 内部和外部都可调用
  • private：只能在定义的合约内部调用（虽然区块链上的数据是公开的，但限制了其他合约的直接访问）
  • internal：只能在内部和派生合约中调用
  • extenrnal：只能从外部调用
  • view：不修改状态（但可以读取）
  • pure：不读取也不修改状态
  • payable：允许函数接收以太币
  • constant： 不允许赋值（除初始化以外），在编译时确定的常量，不占用存储空间。
  • immutable： 可在合约构造时赋值，之后不可更改，存储在代码中。

错误处理

  • error: 自定义错误

  • require：用于输入验证和外部调用的错误检测。

  • assert： 用于内部一致性检查。

  • revert：提供自定义错误消息，回滚状态。

  • contract ErrorHandlingExample {
    function requireExample(uint x) public pure {
        require(x > 10, "x must be greater than 10");
    }

    function assertExample(uint x) public pure {
        assert(x != 0); // 用于内部错误检查
    }

    function revertExample(uint x) public pure {
        if (x <= 10) {
            revert("x must be greater than 10");
        }
    }

    // 自定义错误
    error InsufficientBalance(uint requested, uint available);

    function withdraw(uint amount) public {
        uint balance = address(this).balance;
        if (amount > balance) {
            revert InsufficientBalance({
                requested: amount,
                available: balance
            });
        }
        // 处理提款
    }
}

特殊函数

  • receive：当合约收到纯以太币（无数据）时，就会触发此函数。该函数还必须标记为“payable”。

    • receive() external payable {}

  • fallback: 当合约收到 Ether 并调用合约中不存在的函数时，或者交易中没有提供任何数据时，就会执行该函数。如果希望合约能够以这种方式接收以太币，则必须将此函数标记为payable

    • fallback() external payable {}

全局变量

  • msg

    • msg.sender: 当前调用者的地址，常用于权限验证。
    • msg.value: 当前交易发送的以太币数量，常用于支付逻辑。
    • msg.data: 调用数据的完整字节数组，适用于低级调用。
    • msg.sig: 调用数据的前4字节函数选择器。

  • block

    • block.timestamp: 当前区块的时间戳（Unix时间），常用于时间限制。
    • block.number: 当前区块的编号，可以用于获取链上数据的时间顺序。
    • block.difficulty: 当前区块的难度。

  • tx

    • tx.origin: 交易发起者的原始地址，通常不建议用于权限验证，因为可能导致安全问题。

  • gasleft(): 剩余的Gas量，用于监控Gas消耗。

时间操作

  • 注意事项

    • 区块时间戳的可信度:

      • block.timestamp 可以被矿工稍微操控（但不能偏差过大）。
      • 不适合用于严格的随机性，但适合应用在大多数时间检查场景中。

    • 时间单位的局限性:

      • 不支持高精度（如毫秒或纳秒）的时间。

      • years 不考虑闰年，因此对于时间跨度较长的应用需要自行校准。

  • seconds: 单位秒。

  • minutes: 60 秒。

  • hours: 3600 秒。

  • days: 86400 秒。

  • weeks: 604800 秒。

  • years: 31536000 秒（按 365 天计算，不支持闰年）。

  • uint256 oneMinute = 1 minutes; // 60 秒
uint256 oneHour = 1 hours;    // 3600 秒
uint256 oneDay = 1 days;      // 86400 秒

uint256 startTime = block.timestamp;
uint256 endTime = startTime + 1 days; // 一天后

require(block.timestamp >= endTime, "Time has not yet passed");

  • 使用实例

    • // 倒计时
uint256 public endTime;

function startCountdown(uint256 duration) public {
    endTime = block.timestamp + duration;
}

function isCountdownFinished() public view returns (bool) {
    return block.timestamp >= endTime;
}

    • // 锁定期
mapping(address => uint256) public lockExpiry;

function lockForOneWeek() public {
    lockExpiry[msg.sender] = block.timestamp + 1 weeks;
}

function isUnlocked(address user) public view returns (bool) {
    return block.timestamp >= lockExpiry[user];
}

    • // 限制时间范围
function isWithinTimeRange(uint256 startTime, uint256 endTime) public view returns (bool) {
    return block.timestamp >= startTime && block.timestamp <= endTime;
}

事件类型

  • event: 使用 event 关键字定义。可以定义多个参数，其中某些参数可以被设置为 indexed，用于过滤搜索。

  • anonymous: 匿名事件

    • 不存储事件签名哈希：

      • 匿名事件不会将事件签名的 Keccak-256 哈希值存储在 topics[0] 中。这意味着外部应用在监听和过滤事件时，无法通过事件名称直接过滤匿名事件。

    • 主题位置：

      • 由于事件签名哈希不作为 topics[0] 存储，匿名事件的 topics 数组通常从 topics[0] 开始存储被标记为 indexed的参数。

    • 用途限制：

      • 匿名事件适用于那些不需要通过事件名称过滤的场景，如内部逻辑记录或特定的链上操作记录。
      • 由于缺少事件签名哈希，匿名事件在被外部应用强制过滤时不如非匿名事件直观和高效。
    • pragma solidity ^0.8.0;

contract AnonymousEventExample {
    // 定义一个匿名事件
    event AnonymousDataStored(address indexed sender, uint256 data) anonymous;

    function storeData(uint256 _data) public {
        emit AnonymousDataStored(msg.sender, _data);
    }
}

  • emit: 使用 emit 关键字触发事件。

  • Indexed: 通过 indexed 修饰符，可以对事件的参数建立索引。最多允许 3 个 indexed 参数。

  • sender: 在外部监听器中，可以通过 sender 快速过滤事件。

  • event Transfer(address indexed from, address indexed to, uint256 value);
function transfer(address to, uint256 amount) public {
    // 逻辑处理省略
    emit Transfer(msg.sender, to, amount);
}

function transfer(address to, uint256 amount) public {
    // 逻辑处理省略
    emit Transfer(msg.sender, to, amount);

  • 实例：

    • pragma solidity ^0.8.0;

contract EventExample {
    // 定义事件
    event Deposited(address indexed user, uint256 amount);
    event Withdrawn(address indexed user, uint256 amount);

    mapping(address => uint256) public balances;

    // 触发存款事件
    function deposit() public payable {
        balances[msg.sender] += msg.value;
        emit Deposited(msg.sender, msg.value);
    }

    // 触发取款事件
    function withdraw(uint256 amount) public {
        require(balances[msg.sender] >= amount, "Insufficient balance");
        balances[msg.sender] -= amount;
        payable(msg.sender).transfer(amount);
        emit Withdrawn(msg.sender, amount);
    }
}
