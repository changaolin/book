Paxos

一系列的共识算法，分为支持单个数据协商的Simple Paxos算法和支持多数据协商的Multi Paxos算法族。共识算法和一致性算法的区别是：

  • 共识算法用于群体中达成共识，对共识之后的值并不关心。
  • 一致性算法依据不同的场景会使用不同级别的一致性协议，对一致性的值敏感。
    • 强一致性：任意时刻任意节点的状态保持一致。
    • 线性一致性：所有节点在同一时刻的状态保持一致，只有当所有节点当前状态处理完成之后才会进行下一阶段，否则需要等待。
    • 顺序一致性：允许不同节点在同一时间上存在不同的状态，但对于单个节点而言，协商过程的状态变化顺序是全局一致的。
    • 最终一致性：在容许的时间内，整个系统的各个数据节点的状态达成一致，期间允许某段时间，某些节点的值不一致。

一、 Simple Paxos

Feature

Acceptor 的多数派构成 quorum，2m+1 个 Acceptor 可以容忍 m 个节点fault-tolerant（非拜占庭将军错误）。

Role

  • Provider
    • 接收客户端的Command，提出一个提案（number，value）通过两阶段协商（Prepare-Accepted）达成共识
  • Acceptor
    • 组成公式群体中的大多数，接收或者拒绝提案，提供保证：不会接受比当前提案编号最大值小的的提案。
  • Learner
    • 不具备投票权和提案权，被动的学习群体的共识。可行的一个算法是，Acceptor接受一个提案之后对群体中的Learner进行广播。

Action

  • Proposal
    • Receive a proposal
  • Prepare
    • Receive a Phase 1a PREPARE message containing the proposed ballot
  • Promise
    • Receive a Phase 1b PROMISE message containing the node that generated the promise, the ballot promised and all accepted values within the open window.
  • Accept
    • Receive a Phase 2a ACCEPT message that contains the the slot, proposed ballot and value of the proposal. The ballot contains the node of the leader of the slot.
  • Reject
    • Receives a REJECT message from a peer containing a higher ballot that preempts either a Phase 1a (PREPARE) for Phase 2a (ACCEPT) message.
  • Accepted
    • Receives a Phase 2b ACCEPTED message containing the acceptor that has accepted the slot's proposal along with the ballot that generated the slot.
  • Resolution
    • Receives a final resolution of a slot that has been accepted by a majority of acceptors.
  • Catchup
    • Request sent to a distinguished learner to catch up to latest slot values.

Keywords

  • Ballot
  • Quorum
  • Majority

Process

Phase 1

(a) A proposer selects a proposal number n and sends a prepare request with number n to a majority of acceptors.

(b) If an acceptor receives a prepare request with number n greater than that of any prepare request to which it has already responded, then it responds to the request with a promise not to accept any more proposals numbered less than n and with the highest-numbered pro- posal (if any) that it has accepted.

Phase 2

(a) If the proposer receives a response to its prepare requests (numbered n) from a majority of acceptors, then it sends an accept request to each of those acceptors for a proposal numbered n with a value v, where v is the value of the highest-numbered proposal among the responses, or is any value if the responses reported no proposals.

(b) If an acceptor receives an accept request for a proposal numbered n, it accepts the proposal unless it has already responded to a prepare request having a number greater than n.

二、 Multi Paxos

Multi Paxos算法没有一个具体的实现，但论文中给出了一个实现思路。相比simple paxos的实现， multi paxos使用了一个Leader的角色去主导共识过程，新增了一个slot的概念去存储多个协商过程。相对应的，就需要增加Leader的选举和维持逻辑。

Feature

Role

  • Leader： 对外提供读写接口
  • Proposer
  • Acceptor
  • Instance：节点实体，可以同时具备Leader，Proposer以及Acceptor的角色

Action

  • Receive
    • Bump leadership timeout if the command is not a catchup or proposal
  • Tick
    • Runs logic for a tick of an interval
  • IsLeader
    • Determines if the current node is the leader
  • ProposeLeadership
    • Proposes that the current node take over leadership
  • Decisions
    • Resolved slots within the replica

Keywords

  • DecisionSet
  • Window
  • Liveness
  • Paxos State Machine

Process

  • If enough of the system is working properly, liveness can therefore be achieved by electing a single distinguished proposer.
  • A reliable algorithm for electing a proposer must use either randomness or real time—for example, by using timeouts. However, safety is ensured regardless of the success or failure of the election.
